# 接入指南（如何把新业务套进本骨架）

## 目标

本骨架只提供**协同层**（调度/契约/过审/交接），业务规则由接入实例自带。接入一个新业务 = 在 `instances/<name>/` 下补一份业务规则，不改骨架核心文件。

## 实例目录结构

```
instances/<name>/
├── signal-table.md      # 链路信号词表（调度 Agent 分派用）
├── param-fields.md      # Step 2 参数字段清单（收信息用）
├── chain-<a>/           # 每条链路的生成规则（对应生成 Agent）
│   ├── skill.md
│   ├── playbook.md
│   └── benchmark.md
└── compliance.md        # 过审 Agent 用的合规规则（两级制 + 创作自检清单）
```

## 必填三件套（接入实例必须提供）

### 1. signal-table.md —— 链路信号词表

| 信号词 | 分派链路 |
|---|---|
| （业务关键词） | → chain-a |
| （业务关键词） | → chain-b |

外加「第一目标判定」和「三选一追问话术」。

### 2. param-fields.md —— 参数字段清单

生成 Agent 在 Step 2 要收齐的字段（含默认值），是字段的单一真源。调度 Agent 据此写 brief.md 收齐参数，生成 Agent 读 brief 后据此补收「待追问」字段。

### 3. compliance.md —— 过审规则

含「创作自检清单」（第一级）+「逐条扫描规则」（第二级）+ 违禁词替换表。

## 接入步骤

1. 复制实例模板，改名 `instances/<name>/`。
2. 填 signal-table.md（链路 + 信号词）。
3. 填 param-fields.md（参数字段 + 默认值）。
4. 写各链路的 skill.md / playbook.md / benchmark.md（业务生成规则，可复用已有 skill）。
5. 写 compliance.md（过审规则）。
6. 在骨架 SKILL.md 的「接入新业务」处登记一句。

## 与已有 skill 的关系

- 已有 skill（如 tvc、简历、分镜）的**业务规则**直接复用，只需补「三件套」让调度/过审 Agent 能读。
- 不需要重写业务规则，只补协同所需的接口（信号词、参数、合规）。

## 实例示例：TVC

`instances/tvc/` 是第一个接入实例，复用 jhb-tvc-script 的 hard/soft/story 规则，补三件套：

- signal-table.md：硬广/软广/剧情 信号词 + 第一目标判定 + 三选一追问
- param-fields.md：产品/品类/人群/卖点/价格/预算/平台/画幅/时长/风格/调性/质感（含链路覆盖关系）
- compliance.md：一级违禁词 + 二级项（功效暗示/价值观红线）+ 创作自检清单

## 反模式（接入时避免）

- ❌ 把业务规则写进骨架核心文件（SKILL.md / references/），应放 instances/。
- ❌ 让生成 Agent 兼做调度（判定 + 生成混一个角色）。
- ❌ 让生成 Agent 自审（省掉过审 Agent）。
- ❌ 信号词表、参数字段清单缺失，导致调度 Agent 拍脑袋分派。

## 接入避坑清单（TVC 三轮验证沉淀，新业务接入必读）

以下 9 条是 TVC 实例三轮真实跑通（软广/硬广/剧情）中暴露的规则口径问题，接入新业务时**先自查，避免踩同样的坑**：

> **修复状态（第四轮检查）**：以下 9 条在 TVC 实例文件中已全部落实——①段/镜口径分离（spec-table 通用行已改为「首镜遵循首镜时效表」）、②多段映射表（三链路 skill.md 均已补 30s 段→拍映射说明）、③专属/通用优先级（剧情语速口径已单列说明）、④字数统计口径（storyboard-format 已锁死「不计标点/语气词」）、⑤高风险项进二级扫描（compliance.md 已列）、⑥出镜授权硬前置（compliance.md 已含）、⑦旧术语清理（已 grep 无 router 残留）、⑧语义标注（已用）、⑨引用完整性（已验 19 处引用目标存在）。新业务接入仍按此 9 条自查，但 TVC 实例本身已修复。

### 1. 结构「段」与「单镜」时长口径要分离
- 数值表里常写「CTA 段 3s」「钩子段 3s」，但另有「CTA 镜 ≤2s」「钩子镜 ≤3s」。
- **段是时间轴区间，镜是单镜上限**，一段可由多个 ≤上限 的镜组成。规则里必须明确「段看时间轴、镜看上限」，否则生成 Agent 会把段时长当单镜上限，导致凑不满或超时。
- 例（TVC 硬广）：15s 四拍里 CTA 段是 12–15s（3s），但 CTA 单镜 ≤2s，一段可由 2 个 1.5s 镜组成。

### 2. 多段结构必须给「段→拍」映射表
- 如果数值表里某时长是「六段」「五段」，而 playbook 只定义了「四拍」，两者对不上号。
- **必须补一张映射表**，把每个结构段归到对应的拍（如「痛点」并入 Product、「记忆点」并入 CTA、「沉默/失控」归 Escalation），否则 agent 不知道多出来的段归哪拍。

### 3. 「专属规则」与「通用数值表」冲突时，明确优先级
- 常出现：playbook 写「关键台词 ≤3 句」，但通用语速表写「全片 100–140 字」。
- **必须写明优先级**：专属硬约束（≤3 句）优先，通用数值（100–140 字）只是含旁白/独白的参考上限，不强制凑字。
- 否则过审 Agent 会误判「字数远低于下限」为问题，制造返工。

### 4. 字数/数值统计口径要先锁死
- 台词字数是否计标点、语气词/称呼（如「囡囡？」）算不算关键台词——这些口径不锁，逐镜统计会反复打架。
- **接入时先定一条口径**：语气词/称呼不计入关键台词数，字数按中文字符计、不计标点。

### 5. 高风险项要落到「过审第二级」逐镜扫描
- 每条链路有各自的最高风险项，必须写进 compliance 的二级扫描项，而不是只写在创作自检里。
- 例：软广→功效暗示因果句；硬广→功效绝对化+卖点不唯一；剧情→价值观红线（消费苦难/强行升华/制造焦虑）。

### 6. 出镜授权是「硬前置」，不能靠生成 Agent 自觉
- 老人/儿童/素人出镜的场景，出镜书面授权是投放前硬前置。
- **过审 Agent 必须主动检查**并写进 review 结论（未授权禁投），不能指望生成 Agent 主动提——验证里生成 Agent 都没主动提。

### 7. 「router」这类旧术语残留要清干净
- 从单 agent 迁移到多 agent 时，旧文件里「类型已由 router 判定」这类表述会残留。
- 接入时 grep 一遍旧调度术语（router / 自审 / 两级制在生成侧），统一改成「调度 Agent」「交给独立过审 Agent」。

### 8. 跨层引用用「语义标注」而非「精确相对路径」
- 链路 skill.md 里引用骨架 references 时，写精确上溯路径（`../../../../references/xxx`）极易算错层数。
- **改用语义标注**：写「读骨架 review 语义（由编排层注入）+ 本实例 compliance.md」，由编排层负责把骨架文件喂给对应 Agent。

### 9. 交叉引用路径迁移后要重验
- 把业务规则复制进实例目录后，文件内部的 `references/...` 相对路径会随目录层级变化而断链。
- 迁移后**用 grep 提取所有 `references/xxx.md` 引用，逐个验证目标文件存在**，确保引用完整性。

### 10. brief 交接线要打通，不能「调度写了没人读」
- 最易犯的**协同层**错误：调度 Agent 写了 `brief.md` 收齐参数，但生成 Agent 的 Step 1 只写「链路已判定」、Step 2 直接问用户，过审 Agent 的输入也只写 script.md，**都不读 brief**——调度收的参数被白白浪费，生成/过审又从头问一遍。
- **验讫标准**：`brief.md` 这条线必须闭环——调度写（dispatch.md）→ 生成读（skill Step 1「先读 brief」）→ 过审读（skill Step 5「读 brief 判断合规边界」）。三个角色都 grep 得到 `brief` 才算通。

## 迁移清单（已有 skill → 接入骨架）

把已有 skill 迁移进 `instances/<name>/` 时，按此清单执行：

1. **复制业务规则**（skill.md / playbook.md / benchmark.md / 数值表 / 合规基座）到 `instances/<name>/chain-*/`。
2. **排除被骨架取代的文件**：原 router（→ dispatch.md）、原过审（→ review.md）、原契约（→ contract.md）不复制。
3. **改写生成侧 Step 过审**：把「自审（两级制）」改成「交给独立过审 Agent」，移除生成侧「过审风险清单」输出项。
4. **清旧术语残留**（避坑 7）。
5. **补三件套**（signal-table / param-fields / compliance）。
6. **验证引用完整性**（避坑 9）。
