# 经济性设计（模型分层 + 上下文隔离 + 机械检查优先）

多 Agent 协同最大的隐性成本不是「多几个 agent」，而是**上下文重复加载**和**低级错误跨 agent 传播导致的返工**。本文件继承长剧 pipeline 的三条省钱铁律，套到多 Agent 场景。

## 一、模型分层

| 活 | 用便宜模型 | 用贵模型 |
|---|---|---|
| 链路判定 / 信号词分派 | ✅ | |
| 参数收集 / 追问 | ✅ | |
| 初筛 / 粗写 / 多视角初审 | ✅ | |
| 主体产出（精修脚本/剧本） | | ✅ |
| 独立过审 / 冷审 | | ✅ |
| 最终汇总 | ✅ | |

原则：**判定、搬运、汇总用便宜模型；生成主体和过审用贵模型**。过审尤其值得用贵模型——它是质量闭环的最后一道闸。

## 二、上下文隔离

每个 agent 只喂最小必要上下文，全文不重复加载：

- 调度 Agent：只读实例的「信号词表 + 参数字段清单」，**不读**业务规则全文。
- 生成 Agent：读 brief.md（参数）+ 本链路的业务规则，**不读**其他链路的规则。
- 过审 Agent：读 script.md + 本链路的合规规则，**不读**生成过程的中间稿。

反模式：每个 agent 都把整套 skill 全读一遍——上下文成本随 agent 数线性放大，且挤占模型注意力。

## 三、机械检查优先

「检索 / 对比 / 数数」类检查，先用 Grep 类机械手段跑，清掉低级错误后再进模型视角：

- 禁词 / 违禁词：Grep 命中即替换。
- 跨条 / 跨镜查重：Grep 相同句式。
- 数值一致性：镜头时长加总、字数 ÷ 语速，用脚本算，不靠模型心算。
- header / 字段齐全：校验每个产物文件顶部 header 和必填字段是否齐全。

这条能拦下 **60% 以上**的返工。多 Agent 下更关键：低级错误在 agent A 没清掉，会传到 agent B 被放大，最后返工成本指数级。

## 四、校验前置

容易返工的点提前校验，宁可前面慢一步：

- 方向确认（one-pager）让用户确认后再进主体生成，避免方向错了整批返工。
- 参数收齐再派单，避免生成 Agent 中途追问打断。
- 过审前生成 Agent 先自检一遍机械项，别把低级错误交给过审 Agent 捡。

## 五、并行与串行的取舍

- 多条链路互不依赖 → 可并行（如多个候选方向）。
- 生成 → 过审 → 回改 是串行依赖，不可跳步。
- 过审若拆多视角（合规 + 价值观 + 格式），可并行三路再汇总，比串行快且互不干扰。
