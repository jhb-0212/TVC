# 过审语义（两级制 + review 产物格式 + 越权红线）

## 过审 Agent 的职责边界

过审 Agent **独立于生成**，只标不改。发现问题写 review.md，回改由生成 Agent 执行。

## 输入与输出

- 输入：`workspace/script.md`（生成 Agent 产出）+ `workspace/brief.md`（链路类型与参数，用于判断合规边界）。
- 输出：`workspace/review.md`。

## 两级制过审

### 第一级：创作自检

按实例定义的「创作自检清单」逐条核对（如硬广的「卖点唯一且可视化」、软广的「产品自然融入」等）。清单由接入实例提供，见 adapter-guide.md。

### 第二级：逐镜 / 逐条扫描（强制，不得跳步）

1. 一级违禁词替换、数据引用原则 → 实例的合规基础文件。
2. 二级项 + 链路专项（功效暗示、价值观红线等）→ 实例的专项规则文件。
3. 逐条扫描数字：每个数字必须点名落在哪一镜/哪一条、属于哪一类、如何处理。
4. 产物格式校验：字段齐全、header 完整、数值一致性。

## 输出（review.md 结构）

```markdown
---
task_id: <继承 brief 的 task_id>
chain: <继承>
producer: 过审 Agent
consumer: 调度 Agent
status: review
---

## 结论总览
- 🟢 n 条 / 🟡 n 条 / 🔴 n 条

## 逐条过审
### 产出 1（标识）
- 🟡 第 X 处：<问题> → <改法建议>
- 🔴 第 Y 处：<问题> → <原因>

## 回改清单（给生成 Agent）
- 产出 2 第 Z 处需改：……
```

## 标注含义

- 🟢 可直接投 / 可用
- 🟡 需改词改画面 / 需修改（附建议）
- 🔴 整条不可用（说明原因）

## 越权红线

1. 只标不改：发现问题写 review.md，不直接改 script.md。
2. 不得放水：独立于生成，必须严格，禁止「感觉还行」这类模糊结论。
3. 标 🔴 必须给具体原因和位置，禁止无依据的否定。
4. 换模型冷审：条件允许时用与生成不同的模型过审，交叉挑错更有效。
